# CE-CSL 连续手语训练

## 数据与目标

本次读取用户下载的 `gestureflow/data/CE-CSL`。数据保持原位，训练代码与产物位于独立 SignFlow 项目。

本地检查得到以下数量。

| 划分 | 视频数量 | 用途 |
| --- | --- | --- |
| train | 4,973 | 学习参数、构建词表、计算归一化统计 |
| dev | 515 | 选择最佳训练轮次 |
| test | 500 | 训练结束后评估最佳模型 |

训练集去除独立标点后共有 3,838 个词项，其中 1,893 个仅出现一次，3,177 个出现不超过五次。当前词表包括原标注中的数字及带编号变体，未自行合并词义。

三个划分都包含 A–L 号示范者，当前划分上的评估不能直接推断陌生示范者的效果。标注包含中文句子及 `/` 分隔的 Gloss 词序列，没有逐词动作起止时间。

训练目标为从整段视频预测 Gloss 序列。CTC 根据整句标签学习时间对齐，允许每个词覆盖不同数量的帧。当前流程输出词序列，中文句子的语法生成需要另外评估和实现。

## 特征与模型

1. 按 8 fps 抽取检测帧，图像长边缩放至 640 像素。视频仍需解码，抽帧主要减少关键点检测次数。
2. 每段视频独立创建 MediaPipe Hand / Pose 检测器，避免上一段视频的追踪状态进入下一段。
3. 使用肩膀中心与肩宽归一化位置，保留双手相对身体的位置、手指相对手腕的位置和缺失掩码。二维坐标按图像宽高比校正。
4. 每帧 309 维，包含 33 个人体点的二维位置与有效标记，以及两只手各 21 点的身体相对位置、局部位置与有效标记。不同检测器的深度坐标分别处理，本流程仅使用二维坐标。
5. 训练时拼接相邻帧差分，通过线性投影、两层双向 GRU 和分类头输出每帧词项分布。隐藏维度为 192，采用 CTC 损失。
6. 使用 AdamW、Dropout、轻微特征噪声与梯度裁剪。随机种子为 42，完整实验计划训练 40 轮，每批 16 段视频。
7. 词表与均值、标准差均从训练集计算。验证集和测试集的词表外词项单独记录。

缓存记录提取参数、检测模型 SHA-256 及标注清单摘要。再次提取时复用已完成的特征文件，配置冲突会停止并提示更换缓存目录。

## 运行

以下命令从 SignFlow 根目录执行。`python` 应指向已安装训练依赖的环境，CUDA 版本的 PyTorch 可使用 GPU。

```powershell
python scripts/train_cecsl.py --dataset ../gestureflow/data/CE-CSL --models ../gestureflow/models --workers 6 --epochs 40 --batch-size 16
```

数据集和检测模型也可以放在其他目录，再修改这两个参数。

分开执行提取与训练。

```powershell
python scripts/train_cecsl.py --dataset ../gestureflow/data/CE-CSL --models ../gestureflow/models --stage extract --cache data/cecsl-skeleton-8fps --workers 6
python scripts/train_cecsl.py --dataset ../gestureflow/data/CE-CSL --stage train --cache data/cecsl-skeleton-8fps --epochs 40
```

抽帧阶段可通过再次执行相同命令续用缓存。训练阶段当前重新开始一个实验，保留的优化器状态可供后续扩展恢复训练。

小样本冒烟测试请使用独立缓存与输出目录。其评估结果只检查流程能否执行。

```powershell
python scripts/train_cecsl.py --dataset ../gestureflow/data/CE-CSL --models ../gestureflow/models --limit-per-split 3 --cache data/cecsl-smoke-new --output training/runs/cecsl-smoke-new --epochs 1 --workers 2
```

## 查看进度与结果

特征提取进度在 `data/cecsl-skeleton-8fps/progress.json`，完成后的逐视频检测覆盖情况在 `quality.json`。

每次训练在 `training/runs/cecsl-ctc-时间戳/` 保存结果。可通过 `--output` 指定其他位置。

| 文件 | 内容 |
| --- | --- |
| configuration.json | 网络、词表、划分数量、词表外词项和特征配置 |
| history.json | 每轮训练损失、验证集词错误率与耗时 |
| best.pt | 验证集词错误率最低的模型 |
| last.pt | 最近一轮的模型与优化器状态 |
| dev_predictions.json | 最佳模型的验证集逐条预测 |
| test_predictions.json | 最佳模型的测试集逐条预测 |
| report.json | 完整实验摘要与局限 |

WER 为词级编辑距离之和除以参考词数，包含替换、删除和插入。越低越好，100% 通常意味着全部漏掉或存在同等数量错误，大量插入也可能使其超过 100%。WER 与分类准确率需要分别表述。整句准确率在预测词序列完全一致时才计为正确。

使用训练完成的模型预测一段视频。

```powershell
python scripts/predict_cecsl.py --checkpoint training/runs/实验目录/best.pt --video 你的视频.mp4 --models ../gestureflow/models
```

预测命令会检查特征版本与检测模型摘要，复用训练时的预处理参数、词表与归一化统计。结果打印 `gloss`、帧数与手部检测覆盖比例。

## 当前局限

- 双向 GRU 读取整段视频后预测，实时增量解码需要另外设计缓存和输出稳定机制。
- 骨骼检测的漏手、遮挡、左右手槽位抖动会影响模型输入。
- 当前特征缺少嘴形、面部表情和 RGB 外观信息。
- 同一词的标注变体按原标注保留，训练频率低的词可能难以学习。
- 贪心 CTC 解码使用逐帧最大概率，束搜索和语言模型重打分尚待验证。
- 整句监督下的预测结果需要独立测试，单词练习场景还需要相应测试集。
- 模型文件保存在本地实验目录，训练结果需要经过效果检查后再决定如何接入摄像头流程。

现有摄像头示范匹配与纠错训练继续使用原有入口。数据集、特征、模型权重和私有训练日志均受 Git 忽略规则保护。

训练完成并成功保存模型，最终模型也已通过单视频加载与推理检查。新增单元测试与现有回归测试合计 185 项通过。

测试结果仍有较多识别错误。训练损失由第一轮的 8.35 降至第 40 轮的 0.58，但验证集 WER 后期在较高水平波动，存在明显的泛化不足。使用验证集选中第 28 轮后，测试集仅用于这一次最终评估。

当前可观测的问题包括大量低频词项，以及 31.08% 的抽样帧没有检测到手部关键点。视频中的自然休止、遮挡与检测遗漏均可能贡献这一比例，需通过人工抽查区分。这些现象支持继续优化输入特征和数据利用方式，单纯增加训练轮数未必带来收益。

后续实验优先考虑以下方向，效果需重新验证。

1. 对漏检片段检查原图，评估更高分辨率、手部局部检测与身体手腕引导重检。
2. 引入预训练 RGB 视频特征，与骨骼特征融合，补充手型外观和面部信息。
3. 针对练习系统挑选有足够独立示范的目标词，补充用户摄像头样本，建立单词级与陌生用户测试集。
4. 评估更适合骨架时空关系的网络及预训练方案，并与当前 CTC 基线比较。

最佳实验权重保存在 `training/runs/cecsl-ctc-20261108/best.pt`。当前结果用于后续算法实验比较，实时练习场景的接入需要另行评估。
