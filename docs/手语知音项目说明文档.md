# 手语知音项目说明文档

## 基于视觉感知 示范学习与反馈决策的手语练习智能体

- **项目名称**：手语知音。
- **英文名称**：SignFlow。
- **交互角色**：手语小助手。
- **项目类型**：机器学习与视觉交互课程项目。
- **项目定位**：围绕有限手语词汇开展示范建库、动作检索、纠错学习和练习反馈。
- **文档日期**：2026年11月4日。

> 本文以当前代码、已保存实验报告和开发记录为依据。项目是学习辅助原型，不是通用中国手语翻译器；示范相似度不等同于专业手语规范性评分。

---

## 一 项目摘要

手语知音是一个把视觉识别、用户示范和智能体反馈结合起来的手语练习系统。用户可以上传教学视频，也可以直接通过摄像头录制动作，为视频中的完整动作区间标注含义，建立个性化示范库。随后，用户通过摄像头完成一次新的动作，系统提取关键点序列，与已有示范进行比较，返回相近词义或“未可靠匹配”。

在识别流程之上，项目加入手语小助手。小助手根据用户选择的目标词查找示范，引导用户练习，调用动作分析工具，结合检测质量与比较结果决定下一步，并通过DeepSeek生成容易理解的说明。用户可以重练、纠正错误，并让小助手总结历史练习。

项目的核心链路为：

**示范录入 → 区间标注 → 摄像头练习 → 动作比较 → 结果预览 → 用户纠错 → 识别库热更新 → 后台训练与验证 → 历史回顾。**

当前在线识别主要采用基于示范的DTW序列检索。项目同时建立了小型GRU分类器实验，但没有把训练集高分直接当作上线依据。实验分类器与在线示范匹配的职责分开，便于分析效果和回退。

## 二 问题价值

### 2.1 目标用户

**手语初学者**：能够看教程模仿，但缺少重复练习、回看自身动作和获得反馈的工具。

**希望建立个人词库的使用者**：公开数据集可能不易获得，或者不包含自己想练习的词，需要从自己的教程和录制资料开始建库。

**机器学习与人机交互课程学习者**：需要一个把感知、特征、序列模型、评估和交互串联起来的真实工程案例。

### 2.2 使用场景

1. **从教程整理词汇**：一段视频包含多个词，用户逐段选择动作区间并命名。
2. **摄像头随录随标**：录制后进入与上传视频相同的标注流程，不必另存再上传。
3. **练习已收录动作**：观看示范后，通过摄像头尝试表达对应词语。
4. **纠正误识别**：预览对应片段，填写实际含义，将合格动作加入识别与训练资料。
5. **回顾练习过程**：按词查看次数、可比较程度以及同次多轮练习中的变化。

### 2.3 具体解决的问题

**教程只有展示，缺少实践反馈。** 系统把观看示范与自己的动作采集连接起来，让用户能够反复尝试。

**动作材料难以整理。** 系统支持一个视频连续标多个词，提供倍速、播放位置标记和毫秒微调，降低建库成本。

**识别错误难以复盘。** 系统将结果与具体动作记录绑定，保留判断依据和关键点预览，避免只显示一个无法追溯的标签。

**学习过程缺少连续性。** 小助手保存目标和尝试记录，根据结果安排后续练习，而不是只回答一次识别结果。

### 2.4 实际用途与边界

项目适用于有限词汇的学习演示、个性化示范管理与算法实验。它能够把使用反馈转化为可分析的资料，同时展示小样本识别的真实限制。

当前没有大规模用户研究，不能宣称已经证明显著提升学习效率，也不能替代专业手语教师、无障碍翻译服务或规范认证。

## 四 系统结构

### 4.1 总体结构

```text
用户
 ├─ 上传视频或录制示范
 └─ 选择词语并进行摄像头练习
                 ↓
React与TypeScript前端
                 ↓
FastAPI接口
 ├─ 视频与标注管理
 ├─ 实时采集与诊断
 ├─ 示范匹配与纠错
 ├─ 训练任务管理
 └─ 小助手会话管理
                 ↓
视觉与算法模块
 ├─ MediaPipe关键点检测
 ├─ 手部身份关联与卡尔曼预测
 ├─ 特征提取及缺失标记
 ├─ DTW示范检索
 └─ GRU实验训练
                 ↓
SQLite与本地文件
                 ↓
小助手选择下一步并生成反馈
```

### 4.2 技术选择及原因

| 技术 | 用途 | 选择理由 |
| --- | --- | --- |
| React与TypeScript | 交互界面 | 便于管理摄像头、标注和状态变化 |
| FastAPI | 后端接口 | 便于组织结构化接口和参数校验 |
| MediaPipe | 关键点检测 | 复用通用视觉模型，避免从零训练检测器 |
| OpenCV与FFmpeg相关工具 | 视频处理 | 支持解码、抽帧、裁切和媒体处理 |
| NumPy与SciPy | 特征及关联计算 | 适合数值运算和全局匹配 |
| SQLite | 本地记录 | 便于持久化、备份和追溯 |
| PyTorch | 分类实验 | 支持小型神经网络训练和模型保存 |
| DTW | 动作序列比较 | 能处理同一动作快慢不同的问题 |
| GRU | 时序分类实验 | 保留时间结构，参数规模可控 |
| DeepSeek | 反馈讲解与总结 | 将结构化证据转化为自然语言 |
| Git | 版本管理 | 保存迭代节点，支持回退 |

### 4.3 数据组织

数据分为视频记录、分析结果、示范、纠错训练样本、实时诊断、训练状态和小助手练习会话。

示范记录建立“动作区间—特征序列—含义”的对应关系。诊断记录保留某次识别的边界、候选、特征和耗时。纠错样本则保存用户确认后的含义，并引用原诊断，避免重复提交制造多条相同资料。

这种结构使识别结果可追溯，也使训练和实际使用之间形成数据闭环。

## 五 视觉处理与动作表示

### 5.1 关键点作为输入

手部模型输出21个关键点，覆盖腕部和五指关节。项目使用关键点构造角度、相对距离和运动特征，减少背景、服装等像素信息的直接干扰。

关键点并不等于真实动作。遮挡、模糊、侧向手掌和双手重叠可能造成漏检或错检，因此必须保留缺失与质量信息。

### 5.2 特征工程

当前特征定义包括每手35个通道、双手合计70个通道，以及6个整体通道，共76个通道。主要内容包括：

- 手指关节角度；
- 指尖到腕部的相对距离；
- 拇指与其他指尖距离；
- 手腕位置与二维手掌轴方向；
- 手腕、指尖速度及相关变化量；
- 手与脸部、胸部的距离；
- 双手距离、同步性与追踪状态。

在线检索主要选取其中与手型、距离有关的子集，常见序列包含55个通道。必须区分“提取了某类特征”和“当前算法充分利用了该特征”。完整轨迹融合仍在实验与改进中。

### 5.3 缺失值与掩码

无法可靠获得的特征使用缺失值和有效标记，而不是填成零。零可能是真实测量值，缺失则表示没有测到，两者不能混淆。

当前匹配会比较双方共同有效的通道，因此缺失过多时仍可能出现问题：只剩部分手型，距离却显得较小。后续应进一步研究可靠性加权和缺失惩罚。

### 5.4 手部追踪和卡尔曼预测

系统需要保持同一只手的身份，避免检测顺序变化造成虚假的速度和位置跳变。

卡尔曼滤波的简化状态为：

```text
状态 = [水平位置, 垂直位置, 水平速度, 垂直速度]
```

预测位置用于关联与局部搜索，新的检测结果用于修正预测。预测不能可靠恢复完全遮挡时的五指姿态。

### 5.5 遮挡与模糊处理

项目针对短暂丢失增加了局部加密检测、原图区域重检、其他区域搜索、坐标映射和去重。

短缺口只在前后检测可靠等条件下进行有限补点。补点是估计，不应与真实检测混为一谈。

早期质量规则把可疑骨架标为橙色并整手排除。用户发现部分橙色骨架实际准确，项目据此放宽普通几何警告，保留严重退化和异常数据过滤。前端后来统一显示绿色。

这个过程说明，人工规则也可能错误，必须结合实际样本验证。

## 六 动作匹配算法

### 6.1 基于示范的检索

当前在线识别主要通过保存的动作示范寻找近邻，不是依赖一个已验证成熟的通用分类器。

这种方式适合从有限词汇起步，也允许纠错资料快速生效。但示范质量、输入一致性和区间完整性会直接影响结果。

### 6.2 动态时间规整

同一个动作在不同录制中可能做得快慢不同。DTW允许对时间步进行弹性对齐，寻找两段序列之间的低代价路径。

```text
D(i,j) = c(xi,yj) + min[D(i-1,j), D(i,j-1), D(i-1,j-1)]
```

其中，c表示两个时刻的特征差异，D表示累计代价。项目使用对齐路径的平均距离进行比较。

DTW适应速度变化，但无法自动补回输入中没有表达的动作含义。若两个词的手型相似、运动信息又不充分，仍然可能混淆。

### 6.3 同词多示范综合

算法从“最近一条示范决定结果”调整为：按词分组，综合同词最接近的最多3条示范，再在不同词之间比较。

这样可以减轻单条异常示范的影响。但样本数量不平衡和多个相似示范仍会影响结果，不能认为综合评分已经解决全部偏差。

### 6.4 拒识与解释

系统在最近示范仍较远，或不同词候选过于接近时返回未可靠匹配。

距离是特征空间中的比较值，不是词义概率，也不是学习者的规范分数。主反馈采用易懂语言，技术距离保留在判断依据中。

### 6.5 实时性优化

匹配序列最多取48帧以控制计算量，同时覆盖整段动作。自动识别使用动作快照后台匹配，诊断写盘不再占住采集锁。旧会话结果不能直接串入新会话。

这些改动减少直接阻塞，但Python线程和视觉运算仍会争用计算资源。界面的约14fps是节拍目标，不是所有设备上的保证值。

## 七 机器学习训练与课程知识

### 7.1 监督学习任务

输入为动作特征序列，标签为用户确认的词义。示范区间错误或词义错误，会形成标签噪声，影响模型学习。

项目将用户示范与纠错资料作为训练来源，但标签尚未等同于专业手语审核结果。

### 7.2 GRU实验模型

训练流程为：

```text
动作序列 → 24时间步重采样 → 数值与有效掩码
→ 训练资料标准化 → 32维隐藏状态GRU
→ 最后时刻与时间平均输出组合 → 线性分类层
```

训练使用交叉熵损失和AdamW优化，并加入类别权重和一定扰动。标准化参数应仅根据训练资料计算，预测端使用同一参数。

### 7.3 训练验证划分

项目按来源视频划分，尽量避免同一录制的相似片段同时出现在训练与验证中。纠错样本也保留会话来源。

按视频划分仍不等于跨人验证，同一个人可能录制多段视频。后续需要独立表演者与独立场景的测试。

### 7.4 过拟合

实验中出现训练集100%、跨视频验证较差的情况。这说明模型可能记住拍摄条件、个人特点或检测细节，而不是学到稳定的类别规律。

不能用增加训练轮数代替输入检查和数据设计。应比较特征一致性、数据独立性、模型复杂度和正则化效果。

### 7.5 数据泄漏

需要避免：

- 重复上传同一片段后分入不同集合；
- 同一录制的相邻片段跨训练与验证；
- 刚加入识别库的纠错样本又用自己证明准确率；
- 多次根据开发集调整方案，却把它称为最终独立测试。

“这条纠错动作已经匹配成功”能说明热更新生效，不能证明新录制泛化能力提高。

### 7.6 样本不平衡与评价

部分词有多条示范，部分只有一条。类别权重和同词综合可以缓解一些问题，但不能彻底解决小样本偏差。

后续评价应包含每词精确率、召回率、Macro-F1、未知动作误接受率、跨人表现及端到端延迟，而不只看总体准确率。

## 八 纠错 热更新与后台训练

项目中的热更新包含两个过程。

**识别资料热更新**：用户纠正且片段特征可用后，资料进入后续匹配，不需要重启服务。

**后台实验重训**：读取当前示范和纠错资料，串行执行GRU训练。连续修改合并处理，页面显示排队、运行、完成或失败。

当前重训不等于严格意义上的持续梯度增量学习。新分类器没有无条件自动替换在线识别，因为一次纠正可能包含缺失、截断或标签错误。

同一次动作再次纠正会更新原资料，避免重复样本。普通诊断保存数量有限，已确认训练资料独立保存，不应因诊断轮换而丢失。

## 九 智能体能力

### 9.1 从识别页面到目标驱动流程

普通识别页面主要完成输入到标签的映射。手语小助手围绕目标词组织：

**选择目标 → 查找示范 → 观看 → 采集练习 → 检查证据 → 选择下一步 → 再练 → 回顾。**

系统具有目标、感知、工具、决策、记忆和反馈，适合描述为工作流式学习智能体原型。

### 9.2 工具与职责

| 智能体组成 | 当前实现 |
| --- | --- |
| 目标 | 用户选择练习词 |
| 感知 | 摄像头与关键点检测 |
| 工具 | 示范查询、预览、动作采集、比较与诊断 |
| 决策 | 调整取景、重看示范、再次确认 |
| 表达 | DeepSeek根据结构化证据生成反馈 |
| 记忆 | 练习会话、纠错资料和历史回顾 |
| 闭环 | 用户重练或纠正后继续分析 |

当前工具调用主要由程序组织，并非全部由语言模型通过Function Calling自主选择。不能把已有API编排直接宣称为完全自主规划，也没有把本项目包装成已经实现MCP或向量数据库RAG。

### 9.3 大模型的作用与约束

视觉模块测量关键点、有效信息和比较结果；大模型负责讲解和总结。它没有直接观看当前视频，因此不能编造具体手指、朝向或轨迹错误。

输出规则要求使用日常语言，避免把内部指令、距离和比例直接呈现给用户。接口失败时保留规则反馈，避免外部服务成为整个系统的单点故障。

密钥保存在后端本地配置中，不进入前端或Git。

### 9.4 历史总结

历史总结仅依据已保存记录，统计练过的词、次数和同次多轮练习的变化。只有一次尝试时不宣称进步，跨不同示范和条件的数值不直接作为统一能力分数。

小助手可以帮助用户决定下一次先练什么，但当前没有经过验证的知识掌握模型。

## 十 Vibe Coding需求描述 调试与迭代

项目采用自然语言提出需求、AI辅助实现、真实使用与代码测试共同验证的开发方式。Vibe Coding在这里是一种协作开发过程，不意味着可以省略设计和验证。

### 10.1 需求演进

项目最初围绕手势舞视频分段与教程输出。使用者发现最终结果对骨骼数据利用不足，项目逐步转向含义明确的手语示范学习，并保留已有视频处理和追踪基础。

随后需求从上传视频，扩展为摄像头随录随标；从单词识别，扩展为预览纠错、热更新和学习小助手。

### 10.2 关键迭代

| 反馈或需求 | 修改 | 工程认识 |
| --- | --- | --- |
| 双手重叠漏检 | 加密采样、区域重检和短缺口处理 | 检测与追踪需要分别分析 |
| 模糊后跳变 | 位置预测与关联检查 | 预测不等于还原手指 |
| 橙色骨架实际准确 | 放宽整手过滤 | 规则也会误伤样本 |
| 一视频多个词 | 连续分段标注 | 流程要符合资料结构 |
| 标注不便 | 倍速、位置标记和微调 | 交互成本影响可用性 |
| 总显示上一词 | 当前结果与历史显示分离 | 界面错误会放大算法问题 |
| 希望一纠正就学习 | 识别库热更新与后台重训 | 数据更新与模型更新需区分 |
| 小助手操作繁琐 | 一键准备摄像头与自动提交分析 | 智能体需要组织步骤 |
| 反馈看不懂 | 日常语言与技术依据分层 | 用户不应直接阅读内部字段 |
| 希望总结练习 | 增加历史统计与回顾 | 记忆应服务下一次行动 |

### 10.3 调试教训

曾出现旧服务占用端口，新服务未真正启动的情况。后续通过健康接口和新增路由确认更新生效，而不只检查命令是否执行。

曾尝试镜像匹配、追加运动特征和更严格手部槽位，但实验没有全部改善。项目保留负结果，没有把合理猜测当成已验证结论。

AI辅助开发中，开发者仍需负责需求理解、标签确认、实验公平性、模型替换和数据保护。

## 十一 验证与实验结果

### 11.1 功能测试

文档整理前对本地当前代码执行完整测试，结果为**189项通过**。覆盖特征掩码、区间校验、追踪、纠错幂等、会话隔离、反馈回退和历史统计等。

功能测试证明相应程序行为符合预期，不代表189次真实动作识别全部正确。

### 11.2 分类器实验

| 阶段 | 数据划分 | 验证结果 | 解释 |
| --- | --- | --- | --- |
| 早期全连接模型 | 训练29，验证8 | 0/8 | 验证仅含“在”，覆盖不足 |
| 五词全连接模型 | 训练22，验证7 | 1/7 | 跨视频泛化较差 |
| 同阶段小型GRU | 训练22，验证7 | 3/7 | 有改善但不足以可靠上线 |
| 后续GRU一轮 | 训练33，验证14 | 6/14 | 增加资料未自动消除问题 |
| 整理前最新核实GRU | 训练34，验证14 | 6/14，42.9% | 实验分类器继续保留验证门槛 |

不同资料与划分不能直接当作同条件算法对比。训练集100%也不能作为系统真实准确率。

### 11.3 匹配算法对照

在一组39条跨来源开发资料中，只取最近一条示范为23/39正确；同词最近两条综合为24/39；同词最近三条综合为25/39。

这支持综合多条示范的方向，但它是开发集上的最近候选评价，不是最终摄像头准确率，也没有直接证明最终接受结果精确率。

### 11.4 失败与取舍

- 镜像比较的一组结果从25/29降为19/29，未直接上线。
- 追加相对位移、二维方向等特征的一组结果从25/29降为21/29，保留实验。
- 固定槽位实验从25/29降为24/29，未直接替换。
- 放宽骨架过滤恢复了可用帧，使用反馈改善，但一组离线结果从25/29到24/29，不能宣称离线精度提升。

这些结果说明项目进行了实际比较，而不是只保留有利数字。

### 11.5 性能与用户反馈

一次DTW长度限制对照中，整组离线耗时从约1.01秒到0.79秒，最近候选正确数不变。此结果不能直接等同于端到端延迟降低22%。

用户反馈还促成预览、多词标注、纠错固定目标、随录随标、自然语言反馈和并排布局。当前反馈来自开发使用过程，不是正式受控用户实验。

### 11.6 数据快照

整理时本地数据库有47条示范、16条纠错训练样本、50条保留诊断、9个小助手会话和12次已保存动作分析。示范包含12个用户标注词或短语。

候选资料总数不等于某轮实际训练数，训练还要检查特征版本、重复项与类别划分条件。上述数据会随使用变化。

### 12.4 演示讲解要点

**建库时**：一个视频可以保存多个词，标签由用户确认。

**识别时**：系统比较的是动作序列，不是只看一张截图；不确定时拒识。

**纠错时**：标签绑定具体动作，热更新与神经网络重训分开。

**小助手反馈时**：视觉工具提供证据，大模型负责解释，不凭空评判手指细节。

**训练报告时**：训练集高分不等于泛化，真实验证成绩如实展示。

### 12.5 异常预案

摄像头不可用时展示已有视频；自动切词不稳定时改用手动完整区间；大模型超时使用规则反馈；训练未完成时展示任务状态和上一轮报告。识别错误时展示预览纠错，不把错误隐藏为确定答案。

## 十三 不足与下一步改进

1. **固定独立测试资料**：先分开评估完整动作识别与自动切词，避免混淆错误来源。
2. **统一输入特征**：检查左右手槽位、镜像、尺度、取景与身体参照的一致性。
3. **可靠性加权**：按关节或通道利用信息，避免整手排除或无差别接受。
4. **轨迹与手型融合**：分组比较路径、方向、手型和双手关系，再用验证资料决定权重。
5. **逐词阈值校准**：同时收集正确、混淆与未知动作，避免只放宽阈值提高输出数量。
6. **跨人验证**：扩大独立录制者和设备，不把同一人的多个视频当作充分泛化证据。
7. **时序模型验证**：比较轻量GRU、其他时序结构与DTW基线，保留失败回退。
8. **实时性能测量**：记录端到端中位数和高分位延迟，考虑线程、进程或浏览器感知的取舍。
9. **智能体能力扩展**：在约束下增加多轮追问、示范选择与复习规划。
10. **多用户隔离**：当前本地共享引擎适合单用户，公共服务需要独立会话、权限与数据隔离。

## 十五 常见答辩问答

**问：为什么叫智能体，而不是识别网站？**

因为它围绕目标词保存状态、调用示范与动作工具、根据证据选择下一步，并利用历史反馈形成多轮练习。当前属于工作流式智能体，不宣称完全自主规划。

**问：DTW是不是神经网络？**

不是。它是序列对齐与距离算法，项目把它作为示范检索基线。GRU才是另外训练的时序神经网络实验。

**问：为什么训练集100%却不好用？**

训练集记忆不等于新资料泛化。小样本、标签区间、拍摄差异和特征不一致都可能影响结果，需要用独立验证检查。

**问：纠错后是不是马上训练并切换模型？**

纠错资料可以立即用于匹配，后台另行训练实验分类器；重训完成不等于可以跳过验证自动切换。

**问：当前准确率是多少？**

不能给出一个未经统一测试的总准确率。39条开发资料的最近候选综合对照为25条正确；整理前最新GRU验证为14条中6条正确。任务和划分不同，不能混为一个成绩。

**问：大模型是否直接识别手语？**

当前不是。关键点与匹配模块提供事实，DeepSeek负责解释和历史总结，没有直接观看当前视频。

**问：左右手能不能随便交换？**

不能仅因主导手差异轻易判错，也不能把全部动作的方向和双手关系都视为可任意交换。项目镜像实验没有支持直接上线。

**问：测试通过证明了什么？**

证明被测试的程序行为符合预期，不等于真实手语识别全部正确。

**问：纠错自己再匹配成功能证明模型变好吗？**

只能证明资料进入系统。要证明泛化改善，需要使用未参与更新的新录制。

**问：最优先改什么？**

建立带真实含义的独立摄像头测试，先把切词错误与完整动作比较错误分开，再决定改分段、特征还是模型。

## 十六 可直接使用的汇报开场

大家好，我的项目叫手语知音，是一个基于视觉感知、示范学习和反馈决策的手语练习智能体。

我关注的是：用户看过手语教程以后，缺少重复练习、回看动作和处理识别错误的工具。所以项目先围绕有限词汇实现完整闭环，而不是直接承诺任意手语翻译。

用户可以上传视频或用摄像头录制示范，截取动作区间并标注含义。系统提取关键点，通过时序匹配寻找相近示范，不确定时保留拒识。用户可以预览并纠正错误，合格片段热更新到识别资料，后台另行训练模型。

手语小助手则组织看示范、做动作、分析和重练，用大模型把检测事实解释成自然语言，并根据历史记录进行回顾。

项目与机器学习课程的联系包括特征工程、监督标签、时序模型、训练验证划分、过拟合和数据泄漏。我也保留了失败实验，如实区分训练成绩、开发集对照与真实摄像头能力。

下面我将演示示范建库、摄像头练习、纠错热更新和小助手反馈，再介绍验证结果与不足。

## 十八 项目结论

手语知音已完成有限词汇练习原型中的主要闭环：用户能够建立示范、完成摄像头动作、查看并纠正错误，通过小助手获得后续建议，并回顾练习历史。

它的课程价值在于把视觉感知、序列方法、监督学习、验证与用户交互连接起来，并用真实的失败和改进过程说明机器学习工程的复杂性。

识别精度、跨人泛化、自动切词与多用户能力仍需改进。后续将以独立测试和可追溯证据为基础推进，而不是用训练集高分或一次热更新替代效果验证。
